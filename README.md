Камера не создаёт старый реквизит и свет: новые комнаты задают окружение сами. Боевой баланс сохранён; отклик движения изменён отдельной пробной настройкой ниже.

## Пробное управление по принципу Hades · 06.10.2026

Движение стало быстрее откликаться: единый горизонтальный вектор вместо раздельного разгона X/Z, наземные 65/85 м/с². При 60 Гц реальный разгон — 0,083 с, остановка — 0,067 с, разворот — 0,167 с во всех восьми направлениях. Максимальная скорость остаётся 5,2 м/с. WASD и курсор независимы; направление начатой атаки фиксируется, пробел заряжает прыжок до отпускания. Это пробный отклик нашего слайма, без новой механики рывка.

Импорт, девять существующих наборов и новая физическая проверка при 30/60/120 Гц выполнены; оконный сценарий движения/прыжка/хлыста/паузы/возврата и реальные кадры просмотрены. Удобство пользователем пока не принято. Подробные результаты, ограничения и команды: [отчёт](output/hades_controls_2026_10_06/VALIDATION_REPORT.md). `python3 tools/project.py test` теперь также включает новую проверку управления.

## Запуск

Откройте `project.godot` в Godot 4.7.2 stable и нажмите F5. Из этой папки: `python3 tools/project.py game`, `python3 tools/project.py editor`, `python3 tools/project.py test`, `python3 tools/project.py capture`.

Из родительской папки доступны `npm run game:slime`, `npm run editor:slime`, `npm run test:slime` и `npm run capture:slime`. По отдельному разрешению пользователя обновлены только `../package.json` и `../scripts/slime.mjs`: команды удалённых уровней убраны, тесты работают на общих механиках. Захват проходит три новые комнаты, прыжки, нижний обход, паузу и возврат; реальные кадры находятся в `output/opening_rooms_2026_10_06/images/`.

Прямой запуск на этой машине:

```sh
"/Users/aleksandr/Library/Application Support/Steam/steamapps/common/Godot Engine/Godot.app/Contents/MacOS/Godot" --path "/Users/aleksandr/Documents/ChatGPT/игра/slime-isometric"
```

В меню доступны «Играть», «Настройки» и «Выход». «Играть» открывает `scenes/opening/opening_route.tscn` с прежним героем v5. E у арки переводит в следующую комнату; после галереи доступны повтор и меню. `scenes/level_workspace.tscn` остаётся отдельным стендом. WASD — движение, курсор — направление хлыста, ЛКМ — хлыст, удержание/отпускание пробела — прыжок, колесо — масштаб, Escape — пауза. Из паузы доступны настройки и возврат в меню. Промах в галерее ведёт на нижний настил с пандусом; падение за пределы геометрии возвращает к входу текущей комнаты. Старые снимки при запуске не загружаются и не записываются.

## Проверка и восстановление

Проверки механик используют минимальные физические стенды в `tests/`, а не старые уровни. Эти стенды не входят в экспорт. Отчёт очистки и полный список удалённых файлов: `output/level_cleanup/VALIDATION_REPORT.md` и `output/level_cleanup/deleted_files.json`.

Проверка исправления «Играть», команды и реальные кадры: `output/play_entry/VALIDATION_REPORT.md`. Набор очистки теперь также проверяет реальный вход в сцену, управление, паузу, падение за край, возврат и повторный вход; тест настроек включает стартовую площадку.

Архив до очистки: `output/level_cleanup/backup/source-before-cleanup.tar.gz`; контрольная сумма находится рядом. Он содержит исходники и вложенную лабораторию, без импортного кэша и локальных результатов. Не извлекайте весь архив поверх новых изменений; для восстановления выбирайте нужные файлы.

Соседний исходный проект slime_game, прежние пользовательские снимки и настройки не изменены. Формат CheckpointStore сохранён для совместимости; соответствие старых ID удалённым сценам отключено. Старые снимки не предлагаются к продолжению в меню.
