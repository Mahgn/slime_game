# Карта пути героя

Локальный редактор сюжета. Общий источник данных — `planning/hero-journey/journey.json`: его можно менять в интерфейсе или поручить изменение Codex. Карта не меняет игровой код и не утверждает черновые сюжетные решения.

## Запуск

Дважды нажмите `run_hero_journey.cmd` в корне репозитория. Откроется `http://127.0.0.1:8766/`. Сервер работает в фоне; повторный запуск открывает уже запущенный редактор этой папки. Занятый другим приложением порт не освобождается автоматически. Для другого порта запустите `run_hero_journey.cmd 8767`.

Нужен Python 3.10 или новее. Launcher использует существующий Python из среды Codex, `py -3` или `python`; ничего не устанавливает. Прямой запуск из корня проекта:

```powershell
python planning/hero-journey/server.py --port 8766
```

При прямом запуске остановите сервер сочетанием `Ctrl+C`. При запуске через `.cmd` PID находится в `output/hero_journey/server-8766.pid`. Перед остановкой процесса сверяйте его командную строку: PID со временем может быть переиспользован системой. Журналы сервера находятся рядом.

## Управление картой

- Выберите главу в верхней полосе или «Весь путь». «Карта» показывает направленные связи; «Список» — читаемые события выбранной главы или всей истории.
- Нажмите карточку, чтобы открыть редактор. Сразу доступны название, место, действие и развитие героя; глава, цель, эмоция, раскрытие, условия, статус и заметки находятся в «Ещё детали». Правки автоматически записываются после короткой паузы ввода.
- Перетащите карточку; перенос центра в соседнюю колонку меняет главу. Положение карточки не меняет переходы: они редактируются отдельно.
- «Связать этапы» → выберите начало → выберите конец. Стрелка или список переходов в панели справа открывают редактор связи; там доступны направление, подпись и тип пути. Можно добавить несколько выходов из одного этапа.
- «Добавить этап», «Дублировать» и «Удалить этап» изменяют состав карты. «Удалить этап» находится сразу вверху редактора выбранного этапа. Удаление этапа удаляет его связи; отмена восстанавливает всё вместе.
- Нажатие на крупный заголовок главы на карте выделяет её колонку и этапы. Рядом с заголовком открываются название, описание и действия: переставить, удалить, добавить этап или следующую главу. Новая глава вставляется после выбранной; последующие колонки сдвигаются вместе с этапами. В режиме списка действия также доступны по заголовку.
- «Закрыть» или Escape убирают действия, сохраняя подсветку. Нажатие на пустое полотно снимает выделение. Верхняя полоса глав служит для перехода по карте. «Меню → Название истории» меняет название и описание всей истории.
- У каждой главы есть «Удалить». Для непустой главы можно перенести этапы и все связи в другую главу либо удалить её этапы со связанными переходами. При переносе события располагаются ниже существующих с сохранением взаимного расположения. Удаление и перестановку можно отменить целиком. Последнюю главу удалить нельзя; её можно переименовать и очистить от этапов.
- Тяните пустое поле для перемещения; колесо меняет масштаб вокруг курсора. «Весь экран» или F вписывает выбранную главу/весь путь.
- Ctrl+Z / Ctrl+Shift+Z отменяют/повторяют изменения карты; внутри текстового поля действуют обычные сочетания редактирования текста. Доступны и кнопки в верхней панели. Ctrl+S запускает сохранение сразу.
- В «Меню» доступны поиск, «Скачать JSON», «Загрузить JSON» и справка. Импорт заменяет карту после проверки и подтверждения; его можно отменить.

После отзыва пользователя интерфейс переведён на светлое полотно: постоянной боковой навигации, легенды статусов и вводного текста нет; панель редактирования появляется только после выбора этапа. Данные и связи не перестраиваются при смене оформления.

В исходных данных 28 событий, 28 связей и 6 глав. Факты и предложения разделены статусами; `prototype` означает наличие механической основы, а не подтверждение готовности всей сцены. Начальные источники и рассинхронизации описаны в `CONTENT_NOTES.md`.

## Совместная работа и сохранение

- Сохранение выполняется в `journey.json`; файл пригоден для Git и ручного редактирования.
- Перед каждой реальной записью сервер сохраняет точную предыдущую версию в `output/hero_journey/backups/`. Резервные копии автоматически не удаляются.
- Каждая версия имеет SHA-256 ревизию. Если файл изменён извне или другой вкладкой, устаревшая запись получает конфликт и не заменяет новую версию.
- При ручной правке сохраняйте структуру JSON, уникальные ID и ссылки на существующие главы и этапы. Ошибка JSON или схемы блокирует запись до исправления файла.
- Сервер слушает только `127.0.0.1`. Для работы двух людей на разных компьютерах карта передаётся как JSON либо через обычный репозиторий; сетевого совместного редактирования здесь нет.

Сервер координирует записи открытых редакторов и повторно сверяет файл перед заменой. Внешним файловым редакторам следует завершать правку до сохранения в браузере: между двумя независимыми программами нет общей файловой блокировки.

## Формат и API

`schemaVersion: 1`. Проект содержит `id`, `title`, `subtitle`, `chapters`, `nodes`, `edges`. Поля схемы обязательны; неизвестные поля отвергаются, чтобы опечатки не терялись молча.

- Глава: `id`, `title`, `subtitle`, `color` (`#rrggbb`), `order`.
- Этап: `id`, `chapterId`, `x`, `y`, `title`, `kind`, `status`, `location`, `goal`, `action`, `change`, `emotion`, `reveal`, `requires`, `notes`, `sources`.
- Источник: `label`, `path` (относительно корня репозитория). Все содержательные поля этапа, включая `requires`, — строки.
- Связь: `id`, `from`, `to`, `label`, `kind` (`main`, `branch`, `return`). Развилки и возвраты разрешены; связь с самим собой запрещена.
- Тип этапа: `story`, `combat`, `discovery`, `choice`, `rest`, `finale`.
- Статус этапа: `draft`, `question`, `prototype`, `canon`.

Ограничения: 30 глав, 500 этапов, 2000 связей, файл и запрос до 2 MiB. ID: английские буквы, цифры, `_`, `-`, до 80 символов; первый символ — буква или цифра. Координаты — конечные числа в диапазоне −100000…100000.

| Запрос | Ответ |
|---|---|
| `GET /api/project` | `{project, revision}` |
| `PUT /api/project` с `{project, revision}` | `200` и `{project, revision}` |
| Запись устаревшей версии | `409` и `{error, project, revision}` актуального файла |
| Ошибка JSON или схемы | `400` и `{error}`; файл не изменён |
| `GET /api/health` | Идентификатор редактора и путь текущего проекта |

PUT требует `Content-Type: application/json`, `Content-Length` и Origin, точно соответствующий локальному Host и порту. Нет CORS или доступа к файлам репозитория через URL; JSON доступен только через API. Статические файлы выдаются только из папки редактора, с ограничением расширений и путей.

## Проверки

Из папки `planning/hero-journey`:

```powershell
python -m unittest -v test_server.py
```

Тесты используют временную папку и случайный локальный порт. Рабочая карта при тестировании не изменяется. Проверяются реальные HTTP-запросы, запись и резервная копия, конфликт и конкурирующие сохранения, ошибки схемы/JSON, ограничения запросов, обход путей, Origin/Host и отказ записи при ошибке диска.
